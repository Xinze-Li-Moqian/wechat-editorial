# 发布复制版检查

## 已知成功记录与限制

2026-10-27，用户在使用“公式图片复制版”、去掉链接并调整手机公式大小后，报告“发布成功”。最终交付路径为 HTML 内联样式、正文文本、嵌入图片和富文本复制按钮。此记录不等于对所有公众号账号或浏览器作保证。

当时的失误与具体修正：

- KaTeX 复制产生普通文字、隐藏 MathML、LaTeX annotation 多份内容 → 发布版公式改 PNG，源码另存。
- 出现“不能插入 mp.weixin.qq.com 域名以外链接” → 去掉发布正文 href，包括公式锚点；保留可见文字和编号。
- 手机公式太小 → 将 LaTeX 渲染画布从 420pt 调为 210–230pt，图片按容器缩放。
- 用户在源码编辑器看到 HTML 代码、找不到按钮 → 应打开浏览器预览，而非 `target.type=file` 的源码面板。
- 旧标签过多、queued 被误报为已打开 → 默认复用一个预览标签；确认工具结果，不擅自声称刷新或关闭完成。

## 本次交付

- 使用一个最终 HTML 文件，图像嵌入为 data URI。图片不依赖工作文件夹、外站图片链接或网络字体，正文关键样式内联。
- 图、标题、caption、来源应和当前文章匹配。不要残留上一稿作者、新闻日期或占位词。
- 复制按钮只复制 `#article`，不复制按钮、状态提示、操作说明、JS 或页面外围。只在复制操作返回成功后显示“已复制”。手动“选中正文”应同样只选正文。
- 正文文字逐段核对，尤其引语、数字、译注、公式编号和图片顺序。脚本摘要是结构检查，不替代内容核对或视觉检查。
- 本地预览检查 375px、430px 和桌面宽度；如果工具不能访问本地页面，不绕过权限，不宣称已经验证。可检查已渲染公式和静态结构，并明确尚未进行的检查。
- 有工具权限且用户要求时，可以协助在其目标编辑器预览；制作技能本身不包含发布、购买会员或第三方授权。
- 用户要求右侧展示时，桌面 API 应使用浏览器目标的文件 URL。工具拒绝该目标就停止此路径；不反复创建源码标签，不用被禁止的替代途径。只把 queued 称为已请求。
- 不在没有证据时承诺“一键粘贴必成功”。若用户反馈丢图或错误，先根据实际截图定位原因，修改现有交付文件；不要立即改推荐另一套软件。

## 简短交付话术

给最终 HTML 链接，并说明“打开网页后点『复制全文』，粘贴到公众号正文框”。若新版本覆盖旧文件，提醒刷新后重新复制；已粘贴进公众号的内容不会自动更新。只说明实际存在的限制，不重复解释实现细节。
